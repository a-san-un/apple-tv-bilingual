# AI Session Templates

このファイルは、Perplexity（このチャット）と VS Code の GitHub Copilot / Serena に渡すための
汎用テンプレートと運用ルールをまとめたものです。

- ユーザー → このチャット に渡す「次スレ冒頭テンプレ」
- このチャットがセッション開始時に確認すべきチェックリスト
- このチャット → VS Code の Copilot / Serena に渡す指示文テンプレ（調査 / 実装 / docs）

をまとめた AI セッション用テンプレ集です。

---

## 1. セッション運用方針

### 1.1 役割分担

- Perplexity（このチャット）の役割:
  - 対象リポジトリ / ブランチ / docs を読み、現在位置の整理を担当する。
  - issue / Phase / roadmap / 分割方針をもとに、タスクの切り分け・方針整理を行う。
  - VS Code 側の Copilot / Serena に渡すための、調査 / 実装 / docs 更新用の指示文テンプレを組み立てる。
  - 「変更しない範囲」「完了条件」「不要コード削除・重複回避」などの安全策を明文化する。

- VS Code の GitHub Copilot / Serena の役割:
  - このチャットから渡された指示文に従って、コード調査 / 実装 / docs 反映 / コミット準備を担当する。
  - 2 ファイル以上に波及する変更や、責務境界の追跡が必要な場合は Serena MCP を使って
    影響範囲の確認・差分生成・不要コード整理を行う。
  - 軽微な 1 ファイル修正や、明確な要件がある変更は通常の Copilot 提案で対応する。

### 1.2 基本ルール

- セッション開始時に、対象リポジトリ / ブランチ / 関連 docs を明示する。
- 現在位置の確認には、必要に応じて `docs/dev-roadmap.md` と `docs/contentjs-split-roadmap.md` を読む。
- すでに完了している範囲と、今回戻らない範囲（再調査・再実装しないもの）を整理してから作業に入る。
- 指示文では「目的」「対象」「変更しない範囲」「完了条件」を明示する。
- 変更は最小差分を優先する。
- 既存 helper / 既存フロー / 既存 state を再利用し、別経路のコピペ実装を増やさない。
- 同じ責務の処理を分岐ごとに複製しない。
- 旧ロジックを残したまま新ロジックを継ぎ足さず、置き換えられるものは置き換える。
- ただし削除は「確実に不要」と判断できるものだけに限定し、不確実なものは残して報告する。
- 置き換え後に不要になった旧分岐・未使用変数・古い説明文は削除候補として確認する。
- docs は「ズレが見つかった場合のみ最小差分」の原則で更新する。
- commit / push が含まれる場合は、指示文の早い段階で「今回は commit まで」「今回は push まで」と明示する。

### 1.3 docs の役割

- `docs/dev-roadmap.md`:
  - issue / phase / 状態 / 優先順位 / 次バッチの実装順を書く。
- `docs/contentjs-split-roadmap.md`:
  - `content.js` 分割方針と、Phase A〜E の段階的な進め方を書く。
- `docs/atv-design.md`:
  - UI 仕様、primary / secondary 描画パターン、責務境界、表示ルールを書く。
- `docs/ai-session-templates.md`:
  - AI への依頼テンプレ、運用ルール、調査 / 実装 / docs テンプレを書く。
  - 個別 issue の詳細仕様は書き込みすぎず、再利用可能な形に保つ。

## 2. このチャット用チェックリスト

セッション開始時に、このチャットが確認すべき項目:

- 対象リポジトリ / ブランチ / 関連 Issue / Phase を確認したか？
- `docs/dev-roadmap.md` と `docs/contentjs-split-roadmap.md` を必要な範囲で読み、
  現在位置を把握したか？
- 今回は戻らない範囲（再調査・再実装しないもの）を理解しているか？
- 今回の目的を分類したか？
  - 調査 / 実装 / docs 整備 / push だけ など
- 触らない責務を把握しているか？
  - 例: resolver / secondaryLang fallback / content.js 全面分割 など
- docs は「ズレが見つかった場合のみ最小差分」のルールを意識しているか？
- 重複コードを増やさないルールを意識しているか？
- 今回の変更で不要コード・旧分岐・未使用変数・死んだ説明文が発生しないか意識しているか？
- 「既存処理へ寄せる」のか「新規追加が本当に必要」なのかを切り分けたか？
- 今回の作業が Serena MCP を使う条件に当てはまるか確認したか？
  - 2 ファイル以上に波及
  - 影響範囲が読みにくい
  - 既存ルールとの整合確認が重要
- 条件に当てはまる場合、下のテンプレから適切なものを選んで Copilot / Serena 用指示文を作ったか？
- docs 更新時に、どの内容を `dev-roadmap` に書き、どの内容を `atv-design` に書くべきか切り分けたか？

## 4. 共通ルール（実装・docs 共通）

- 変更は最小差分を優先する。
- 既存 helper / 既存フロー / 既存 state を再利用し、別経路のコピペ実装を増やさない。
- 同じ責務の処理を分岐ごとに複製しない。
- 今回の issue の責務を超える全面リファクタリングは行わない。
- docs 更新は、内容のズレが見つかった箇所に限定し、短い追記・文言修正に留める。
- 実装でも docs でも、変更によって不要になった旧記述・旧分岐・未使用変数・死んだ説明は削除候補として確認する。
- 旧ロジックを残したまま新ロジックを追加する形は避け、置き換えられるものは置き換える。
- ただし、削除は「確実に不要」と判断できるものだけに限定し、不確実なものは残して報告する。
- 既存コメントは壊さず、責務境界を補う短いコメントを必要箇所へ追加する。
- commit / push を含む場合は、指示文の早い段階で「今回は commit まで」「今回は push まで」と明示する。
- docs の粒度は役割で分ける:
  - 実装順 / 優先順位 / phase 管理 → `docs/dev-roadmap.md`
  - 画面仕様 / UI ルール / 描画パターン / 責務境界 → `docs/atv-design.md`
  - AI への渡し方 / テンプレ / セッション進行ルール → `docs/ai-session-templates.md`

## 7. docs 更新テンプレート（このチャット → Copilot / Serena）

```text
VS Code の GitHub Copilot / Serena MCP でこのプロジェクトを有効化してください。
プロジェクト名:
対象ブランチ:

今回は docs 更新のみです。実装コードは変更しません。

目的:
-

対象ファイル:
- docs/...

やってほしいこと:
1.
2.

制約:
- 変更は最小差分
- 既存文を大きく書き換えない
- トーンは既存 docs に合わせる
- 内容が最新実装と矛盾していないか確認してから書き換える

不要記述削除・重複回避（毎回必須）:
- 実装変更で古くなった説明があれば削除または更新する
- 同じ説明を複数ファイルに重複して書きすぎない
- docs ごとの役割に合わせて粒度を分ける
- ただし、必要な背景説明まで削らない

完了時の報告:
- 変更ファイル一覧
- 各ファイルで何を変えたか
- 削除した古い記述や重複記述
- 変更不要と判断したファイル
```

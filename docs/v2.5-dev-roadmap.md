## 更新方針

- 既存 issue（#3〜#8）は基本的にそのまま使用する。
- ただし、手動検証の結果を踏まえて、**優先順位・フェーズ・完了状態を更新**する。
- 特に、popup / options の言語候補が動画状態に依存して変化する問題があるため、まずは設定 UI の安定化を優先する。
- そのため、従来の「UI 安定化 → 設定整理」の順ではなく、**設定 UI の固定化と再生 UI 安定化を同じ Phase 1 で扱う**。
- なお、[#5](../../issues/5) は `options.html` / `options.js` の修正と関連コミットが確認済みのため、**完了済み** として扱う。

## フェーズ構成

### Phase 1: 字幕選択と再生 UI の安定化

**ゴール**: popup / options の言語設定が動画状態に依存せず安定して表示され、secondaryLang の空値運用を含めた設定 UI が一貫して扱えること。
加えて、動画再生 UI が右字幕パネルに妨げられない状態を作る。

- [ ] [#6] 固定言語一覧ベースへの変更と UI からの textTracks 生データ分離
- [ ] [#7] secondaryLang 空値許容とブラウザ言語 fallback 前提の UI 整理
- [ ] [#3] 動画操作レイヤーの重なり解消

### Phase 2: Debug UI 整理

**ゴール**: Debug UI が常時浮かず、必要なときだけ右字幕パネルや options から確認できる状態を作る。

- [ ] [#4] ATV DEBUG を字幕パネル下部に統合
- [x] [#5] options の Debug セクション折り畳み既定化

### Phase 3: ログ基盤整理

**ゴール**: options と字幕パネルが同じログソースを共有し、必要なカテゴリだけを既定表示できること。

- [ ] [#8] Debug ログカテゴリ設計整理

## Phase 1 の補足メモ

### 1. 字幕選択 UI

- popup / options の言語選択肢は、動画ごとの `textTracks` の生データをそのまま出さず、固定一覧ベースで扱う。
- 設定 UI では、`en`, `ja`, `de` のような正規化済み言語コードに対応する **1 言語 1 項目** だけを見せる。
- `English (forced)` のような forced 表記は、UI の直接候補にしない。
- `primaryLang` は必須、`secondaryLang` は空保存を許容し、content 側でブラウザ言語 fallback を適用する。

### 2. 今回の #6 / #7 の対象範囲

- 今回は **固定言語一覧ベースへ変更し、UI で textTracks の生データを直接見せない** ところまでを主対象にする。
- `secondaryLang` の空値保存とブラウザ言語 fallback 前提の UI 整理は、#7 の関連範囲としてあわせて進める。
- forced 字幕を UI の直接候補に出さない件は、#6 の補足仕様として扱う。
- `textTracks` の厳密な正規化や resolver 導入は、今回の #6 実装対象には含めず、必要なら別 issue / 後続タスクとして整理する。

### 3. 動画レイアウト調整

- `video-player__content` を基準に、動画本体と再生コントロール系を左側の責務としてまとめる。
- 右 30% は字幕パネル専用領域として維持する。
- Apple TV+ 側の一時表示 overlay（例: skip overlay）は常時 DOM に存在しない可能性があるため、状態依存で検証する。

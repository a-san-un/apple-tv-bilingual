17-A-9 の中心は、**「いま分割した各 module を、読み込み順・公開面・参照入口の3点で固定すること」**です。[1]
現在の repo では `manifest.json` が `panel-renderer.js` → `panel-ui.js` → `subtitle-blocks.js` → `subtitle-block-resolver.js` → `content.js` の順で content script を読み込み、各 module は `window.ATVB` / `globalThis.ATVB` に公開され、`content.js` がそこから取得しています。[1]

## 17-A-9 の具体的な作業内容

### 1. module 公開面の固定

各 module が外に公開する API を最小限に絞り、`content.js` が依存する入口名を固定します。[1]
現状の主入口は `panel-ui.js` の `ATVB.panelUi.createPanelUi`、`panel-renderer.js` の `ATVB.panelRenderer.createPanelRenderer`、`subtitle-blocks.js` の `buildSubtitleBlockSequence`、`subtitle-block-resolver.js` の `resolvePanelBlocksForRender` です。[1]

この枝番でやることは次の通りです。

- `panel-ui.js`: `createPanelUi` のみを正式公開面として扱う、内部 helper を外部契約として増やさない。[1]
- `panel-renderer.js`: `createPanelRenderer` のみを正式公開面として扱う。[1]
- `subtitle-blocks.js`: `buildSubtitleBlockSequence` を正式公開面として扱い、補助関数は module 内部へ留める。[1]
- `subtitle-block-resolver.js`: `resolvePanelBlocksForRender` を正式公開面として扱う。[1]

### 2. content.js の参照入口整理

`content.js` はすでに `window.ATVB?.panelUi?.createPanelUi`、`window.ATVB?.panelRenderer?.createPanelRenderer` を読んでいますが、17-A-9 では **この参照の書き方を一箇所に寄せる** のが重要です。[1]
つまり、「どこで module を掴むか」「取得失敗時にどう落とすか」を冒頭の module resolution セクションへ集約し、その後は局所変数だけを使う形に揃えます。[1]

具体的には次を確認・整理します。

- `createPanelUi` 取得箇所を唯一にする。[1]
- `createPanelRenderer` 取得箇所を唯一にする。[1]
- `buildSubtitleBlockSequence` の取得元が `subtitleBlocksDeps` などに散っていれば集約する。[1]
- `resolvePanelBlocksForRender` の fallback / default 実装があるなら、その存在理由をコメントで固定する。[1]

### 3. manifest の読み込み順固定

現在の `manifest.json` では、依存関係に沿って module 群が `content.js` より前に並んでいます。[1]
17-A-9 ではこの並びを「偶然動いている順」ではなく、**依存順として明示的に固定**します。[1]

実作業としては次です。

- `panel-renderer.js` が `content.js` より前にあることを維持する。[1]
- `panel-ui.js` が `content.js` より前にあることを維持する。[1]
- `subtitle-blocks.js` / `subtitle-block-resolver.js` が `content.js` より前にあることを維持する。[1]
- 将来の並び替え事故を防ぐため、`manifest.json` の `content_scripts.js` 配列に「panel-related modules / subtitle pipeline / orchestrators」などのコメントは入れられないので、代わりに設計メモか docs 側へ読み込み順のルールを残す。[1]

### 4. namespace 形の整合

現状は `panel-ui.js` と `subtitle-block-resolver.js` が `globalThis.ATVB` / `window.ATVB` に直接書き込み、`panel-renderer.js` と `subtitle-blocks.js` も `window.ATVB` を root に使っています。[1]
17-A-9 では、namespace の切り方を揃える確認も必要です。[1]

作業内容は次です。

- `ATVB.panelUi.createPanelUi` のように「名前空間オブジェクト配下」へ揃える。[1]
- `panel-renderer.js` も `ATVB.panelRenderer.createPanelRenderer` になっているか確認する。[1]
- `subtitle-blocks.js` と `subtitle-block-resolver.js` も、公開名の切り方を揃える。少なくとも `content.js` 側から見た取り方が一貫するよう整理する。[1]

### 5. 旧 API / 旧名前の残骸除去

17-A-9 では「今は動くけれど、旧 refactor 前の呼び方が残っている」状態を掃除します。[1]
これは 17-A-10 の API 固定に直結します。[1]

今回の panel 周りで見直す対象は次です。

- `destroyUiHosts` のような互換 alias を今後残すかどうか判断する。[2][1]
- `content.js` 側に古い module 直参照や fallback 名が残っていないか確認する。[1]
- 例外メッセージの文言を、正式 API 名に合わせて整える。現状は `ATVB panelUi.createPanelUi is not available`、`ATVB panelRenderer.createPanelRenderer is not available` で揃っているので、この方針を維持する。[1]
